# Strict Ed25519 key and scalar validation

Generated by `scripts/gen-vectors.ts` (section 11); do not hand-edit.

**Rule.** Every verifier in this repository applies strict public-key validation at key load,
from the key bytes alone and before any signature is examined: it refuses non-canonical and
small-order Ed25519 key encodings (RFC 8032 §5.1.3 decoding + small-order rejection). A keyring
public key is refused when

1. its y coordinate (the low 255 bits) is not canonical (y >= p);
2. y does not decode to a curve point (x^2 = (y^2 - 1) / (d*y^2 + 1) has no square root);
3. x = 0 and the sign bit is set (RFC 8032 §5.1.3 step 4);
4. the point is in the small-order torsion subgroup (any of the 8 points, in any spelling).

A signature is refused when its scalar S is not canonical (S >= L, RFC 8032 §5.1.7).

A key produced by Ed25519 key generation passes every step, so no valid key or signature changes
verdict.

**Vectors.** Each `keyring-*.json` maps the corpus kid to one refused public key. Verified with
`../valid-chain.json`, whose receipts are genuine, every keyring must yield `TAMPERED` (exit 2) in
all five verifiers: a small-order public key must be refused at key load, and so must every
non-canonical or off-curve encoding. `chain-s-not-canonical.json` is `../valid-chain.json` with
the second receipt's signature re-encoded as S + L; with `../keyring.json` it must yield `TAMPERED`.
